**设计假设（重要）**：
- 批量删除语义 = 删本地行 + 删浏览器书签（对 bookmark 来源）。**Star-only 条目仅删本地行，下次 GitHub 同步会重新出现**——确认弹窗已明示；彻底移除需用户在 GitHub 取消 Star（MVP 保持 GitHub 只读）。
- `bookmarks` 写权限已在两处使用：右键快速收藏（前序）与批量删除（本次）。商店审核文案需相应更新（不再是"只读"）。
- 导出走页面上下文 `Blob + a[download]`，不经过 runtime message（避免大 payload），零新增权限。

## 三、架构备忘（新会话必读）

- **消息协议**：UI ↔ SW 走 `core/msg.ts` 的 `BgRequest/BgResponse`；`batch` 是唯一的写操作扩展点（`applyBatch`）。
- **索引失效链路**：任何 items 变更后必须 `bumpIndexVersion(ids)` → storage 事件 → 面板监听 → worker `invalidate`（ids 增量 / null 全量）。写代码时不要绕过这条链路。
- **meta 计数**：`items` 变更必须走 `upsertItems / updateItem / applyBatch / transformItems / stripSourceForUrls` 这些已维护计数的入口，不要直接 `db.items.put`。
- **导出**：`buildExport(format, items)` 纯函数，items 用 `db.items.bulkGet(ids)` 或 `toArray()` 现取；UI 侧负责 Blob 下载。
- **规则存储**：`chrome.storage.local.tagRules`（用户配置，不是条目数据，不入 IndexedDB）。
- **测试环境**：vitest node + fake-indexeddb；依赖 `browser.*` 的代码路径在测试里要 mock `wxt/browser` 或绕开（如 `deleteBookmarks:false`）。

## 四、已知限制

1. Star 来源无法真正"删除"（GitHub 只读），批量删除后会在下次同步回归。
2. 规则命中的标签是追加式：用户手动移除后，下次同步/应用会再加回（符合规则语义，面板文案已提示）。
3. 导出 HTML 目前是平铺列表（TAGS 属性带标签），未按书签文件夹路径重建目录树。
4. `.output/` 下的构建产物不入库；交付用 `npm run build` / `npm run zip` 现场生成。
