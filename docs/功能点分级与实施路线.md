# StarMark 功能点分级与实施路线

> 依据 `docs/功能扩展点.md` 整理，按**实现难度**分级；对冗余/与产品定位不符的功能点予以暂缓并说明原因；并补充一些能与现有架构产生**联动**的新功能想法。
> 关联：`docs/开发技术文档.md`（技术选型与架构）、`docs/产品设想.md`（产品定位）。

---

## 一、分级标准

| 分级 | 含义 | 通常成本 | 对现有架构的改动 |
|------|------|---------|------------------|
| **T1 简单** | 数据/字段已就绪，主要做 UI 层或已实现逻辑的收尾 | ≤ 1 个迭代（1~3 天） | 小改动，无新权限/新后端 |
| **T2 中等** | 需要新增模块、UI 复杂度高、或引入新权限/写操作 | 1~2 个迭代 | 复用核心层（Dexie/MinimumSearch/同步状态机） |
| **T3 困难/边缘** | 依赖 ML、后端服务、跨应用生态或重架构 | ≥ 1 个迭代以上 | 通常涉及外部依赖或新产品边界 |

> ✅ = 当前 MVP 已实现或已有基础（标注 "@/部分/能力已就绪）。

## 二、分级总览

### T1 简单（优先做，成本低见效快）

| 功能 | 说明 | 现有基础 |
|------|------|---------|
| 排序与筛选 | 按 时间/名称/Star数/语言/来源 排序与筛选结果 | ✅ 数据字段齐备（starredAt/dateAdded/starMeta） |
| 统一标签系统（基础版） | 本地 tags 字段赋色/重命名，结果卡片与筛选联动 | ✅ 文档 §17 已预留 `tags` 字段 |
| 笔记 / 收藏理由（基础版） | 每条目简单笔记 + 收藏时填写理由，随条目展示 | ✅ 字段已预留 |
| 来源感知智能排序 | 搜索时按场景调整书签/Star 权重，结果分组展示 | ✅ 搜索 Worker 分组混排已有 |
| 同域名聚合与智能分组 | 结果按域名聚类 + favicon 展示 | ✅ `normalizeUrl` 已去重，域名可直接取 |
| 自动去重（增强） | 标题近似去重提示，合并建议 | ✅ URL 级去重已实现 |
| 增量同步 → 变更视觉化 | 把已计算的「新增/取消 Star」做成最近动态时间线 | ✅ 同步状态机已带检查点与 diff 能力 |
| 统计仪表盘（基础） | 总量/来源占比/语言分布/最近趋势，纯本地查询 | ✅ 数据在本地，无需后端 |
| 健康度评分（基础） | 唯一域名数、未整理标签、重复、超龄清单 | ✅ 同上 |
| 敏感书签隐藏 | 单条目 `hidden` 标记 + 过滤开关 | 小改动 |
| 加密备份导出（简化版） | 一键导出 JSON（可选简单口令加密）下载 | `chrome.downloads` 即可，无新权限风险 |
| 快速收藏（右键菜单） | 右键当前页「收藏到 StarMark」并顺手写备注 | 复用书签事件增量链路，仅 +contextMenus |
| 同步体检/诊断页 | 展示 syncState 检查点与最近错误，弱网友好提示 | ✅ syncState 表已完整 |

### T2 中等（第二梯队，形成「管理」深度）

| 功能 | 说明 | 关键依赖 |
|------|------|---------|
| 标签系统（完整版） | Emoji/颜色/批量打标/标签筛选页 | tags 字段 → 独立标签表/UI |
| 批量操作与导出 | 批量加标签/删除，导出 CSV/HTML/Markdown（含预览） | 导出模板 + 写入确认 |
| 一键互相转换 | 结果卡片「加为书签」/「Star 此仓库」 | ⚠️ bookmarks 写权限 + GitHub star/unstar API |
| 命令面板 + 键盘导航 | Ctrl⌘+K 唤起、vi 风格导航、自定义快捷键 | 与侧边栏共用搜索内核 |
| 新标签页覆盖 | 自定义新标签页集成搜索入口 | newtab 入口复用 Worker 快照 |
| AI 自动分类与摘要（BYOK） | 用户自带 Key，对条目批量生成标签/摘要；可复用同步状态机做可恢复流水线 | 文档 §17 已预留 Provider 抽象 |
| AI 审核机制 | AI 建议暂存，用户批准/拒绝/合并后才写入 | 新建「建议桶」表 |
| 规则自动分类 | 「域名含 youtube → Videos」等 URL/语言/关键字规则引擎（简化版） | 与标签系统联动 |
| 间隔重复回顾 | 按 starredAt/dateAdded 生成「待复习包」，卡片自测 | 与仪表盘/时间线同源 |
| 回顾/智能提醒 | 可选 content script，打开页面时提示相关已存内容 | ⚠️ 需 host_permissions/content_scripts（可选开启） |
| URL 批量重写与域名迁移 | 域名/正则替换批量更新书签 | ⚠️ 写操作，需确认 UI 与回滚 |
| 双向同步与原子替换 | 快照完整性校验后再替换本地数据 | 同步状态机增强（校验/回滚） |
| 分类注册表与安全重命名 | 稳定 ID（本地 DB 已天然具备）、重命名保留关联 | 与书签文件夹 ID 绑定 |
| GitHub Lists 双向同步 | 标签 ↔ GitHub Lists（2024 GA） | ⚠️ 需要 star:write 权限 |
| README 在线预览 | Worker 拉取 raw README，DOMPurify 清洗后展示 | ⚠️ 需 host_permissions + sanitize 库 |
| 多视图模式 | 列表/卡片/紧凑视图切换 | 纯 UI |
| 热力图/柱状图可视化 | 收藏日历热力图、语言分布 | 图表库（轻量/自绘） |
| 收藏趋势报告（简化版） | 周期趋势 + 清理建议列表 | 数据已在本地 |
| 冷启动引导（二次收藏） | 新用户主题偏好引导，渐进个性化 | 与基于内容的推荐衔接 |
| Obsidian 同步（简化版） | 一键导出标准 Markdown（frontmatter: tags/来源/备注）下载或走下载 API | 无需写权限，避开 FS 限制 |
| 多浏览器支持 | Firefox 用 Popup 兜底侧边栏 | WXT 已内置多浏览器构建 |

### T3 困难 / 前瞻（列入远期，不做近期承诺）

| 功能 | 说明 | 卡点 |
|------|------|------|
| 语义搜索 / 向量嵌入分组 | 本地嵌入 + 余弦检索 | MVP 暂缓，文档 §17 已留 `embedded` 字段 |
| AI 问答式检索 / 内容问答 | 对收藏/存档内容做带引用的问答 | 需全文存档底层 |
| 完整页面离线存档 / 全文检索 | 无头浏览器 + monolith 级存档 | 产品边界接近 Karakeep，体量大 |
| 截图缩略图、OCR、视频保存 | 多媒体捕获 | 需要 offscreen/媒体管线 |
| 本地 AI 模型（Ollama） | 离线推理 | 需额外进程/本地服务，非浏览器内可完成 |
| Watch Inbox / 通知汇总 | GitHub 通知与 Star 关联 | 依赖通知 API + 多仓库轮询（限流） |
| Release 追踪时间线 | 订阅仓库版本统一时间线 | 多仓库轮询，速率限制开销大 |
| 跨设备同步（WebDAV/Gist/Serverless） | 加密存储 + 服务端 | 后端/第三方服务 |
| REST API / Webhook / MCP 服务器 | 对外生态接口 | MV3 SW 无法常驻监听端口；MCP 需 Native Messaging 宿主 |
| 个性化推荐（协同过滤/LLM零训练） | Trending 数据管道 + 推荐理由 | 依赖数据管道与模型 |
| 共享/团队/协作收藏 | 多人权限 | 需后端，与本地个人工具定位冲突 |
| E2E 加密存储 | 全库加密 | chrome.storage 已隔离，加密收益低、成本高 |
| Obsidian 深度联动（双向链接/Canvas/MCP） | 双向回写 Observer 生态 | 依赖 Obsidian 端插件/协议 |

## 三、建议暂缓或忽略（冗余 / 与定位不符）

> 原则：StarMark 定位「**做了极致的查找，顺便做轻量管理**」，不做重后端、重社交、重内容归档。

| 功能点 | 原因 |
|--------|------|
| 完整页面离线存档 / 全文内容检索 / OCR / 视频保存 | 与 Karakeep/Shiori 撞车，属「存档型产品」；需求和维护成本是搜索工具的 10 倍 |
| 团队书签库 / 共享收藏集 / 权限管理 / 类 Git 协作 | 需要账号与后端，与「纯本地个人工具」定位冲突 |
| 多配置文件 | 用例极少，书签树本身可分「书签栏/其他书签」 |
| 浏览器书签自动同步 | Chrome/Firefox 自带账号同步 + Floccus 已覆盖，重复造轮子 |
| E2E 端到端加密 | `chrome.storage` 已隔离 + 扩展 CSP 收敛；加密工程收益低 |
| 自动锁定 / 非活动超时 | 侧边栏随窗口/标签生命周期自然消失，无「常驻锁」场景 |
| 视频/媒体保存、本地 Ollama | 需要系统级进程，浏览器扩展无法优雅承载 |
| 第三方同步生态全家桶（Raycast/Obsidian/Telegram/FreshRSS…） | 生态深水区；先做「一键导出通用格式」即可覆盖 80% 需求 |
| 语义搜索 + 相似度分组（与十、重复条目） | 已在 T3 统一计一次 |
| Trending/推荐相关多数条目 | 数据管道与模型的运维成本高，前期收益低；保留「冷启动引导」即可 |

## 四、新增功能点建议（我的想法，注重联动）

> 这些想法**复用现有能力**（Dexie、MiniSearch Worker、同步状态机、normalize 去重、star+json 时间戳），多数是 T1/T2，且互相有乘法效应。

### 1. 「入舱链路」：快速收藏 + 右键菜单 + 备注
- 右键「收藏到 StarMark」：直接调用书签 API 新建书签 + 顺手弹「一句话理由」输入框 → 复用已有书签事件增量链路自动入库。
- **联动**：与 T1 笔记/收藏理由、一键互转形成完整「收藏→记录→管理」闭环；书签读写权限可选，不强制全局申请。

### 2. 「时间线」：把增量同步变成可视化 Feed
- 已有 `starred_at / dateAdded` 与取消 diff，仅差一个 UI：切换「动态」视图，滚动看「本周新增 Star / 最近收藏 / 最近移除」。
- **联动**：间隔重复回顾、健康度趋势、统计仪表盘全部复用同一时间维度索引 → 一个视图四吃。

### 3. 「多入口矩阵」：侧边栏 / 地址栏 / 命令面板 / 新标签页 共用同一搜索内核
- 现有 Worker 快照 + `storage.session` 轻量建议，天然可扩展到 newtab 与 Ctrl⌘+K 面板。
- **联动**：评分、收藏理由、快捷键在不同入口下一致，打造「无论在哪都能一句搜到」的品牌体验。

### 4. 「来源感知 + 一键互转」组合拳
- 搜索结果里，Star 项给「🔖 存为书签」、书签项若匹配 GitHub 仓库给「⭐ 加 Star」按钮（均需确认与可选权限）。
- **联动**：互转后 `sources` 合并去重（已实现），两个孤岛真正打通。

### 5. 「回顾模式」（轻量间隔重复）
- 用时间戳算出「该复习的收藏」，生成卡片组：看到标题 → 回想哪里用 → 点开验证 → 打「记住了 / 忘了 / 移除」。
- **联动**：把搜索工具延伸成个人检索记忆系统（对标 Markline，但轻得多），数据全部本地。

### 6. 「规则标签 + AI 建议标签」双轨
- 规则引擎产出的标签标「规则」，AI 建议的标「待审核」；用户一次确认后合并进统一标签系统。
- **联动**：标签 → 筛选 → URL 互转 → 导出，形成管理主链路；审核桶与 AI 流水线（T2）无缝衔接。

### 7. 「一键导出宝库」
- 导出按钮：JSON（完整备份）/ Markdown（Obsidian frontmatter 风格，含 tags/理由/来源）/ HTML（浏览器原生导入格式）。
- **联动**：Obsidian 生态 80% 需求 ≈ 一次导出；也是「跨设备搬迁」的轻量替代。

### 8. 「健康度 + 清理清单」面板
- 启动时后台计算：重复地址、超期未整理、孤儿标签、无理由收藏 → 生成一键清理建议（只做建议，不做自动删除）。
- **联动**：与仪表盘、自动去重、导出联合，构成「专业感」的三件套。

### 9. 「同步体检页」
- 展示 syncState 检查点、最近一次同步耗时、各阶段耗时、错误列表（401/429/断网），弱网下给出「等会儿自动重试」的状态文案。
- **联动**：复用状态机日志，几乎零成本提升「可信度」；也是 MVP 阶段最有性价比的「正规感」功能。

## 五、推荐实施顺序（三阶段）

> 遵循功能点清单的「核心原则」：**先做极致查找，再做轻量管理，最后 AI/生态深度**。

**阶段 A（查找体验收尾，全 T1）**
快速收藏+备注 · 时间线 Feed · 多入口（命令面板/新标签页） · 来源感知排序 · 同域名聚合 · 同步体检页

**阶段 B（轻量管理，T1→T2）**
标签系统（基础→完整） · 笔记/收藏理由 · 规则标签 + AI 建议标签 · 一键互转 · 批量操作与导出 · 回顾模式 · 健康度与清理清单

**阶段 C（AI 与生态，T2→T3）**
AI 分类/摘要（BYOK + 审核机制，复用同步状态机） · GitHub Lists 同步 · README 预览 · Obsidian 一键导出 · 跨设备同步 · 语义搜索（收尾，字段已预留）

---

## 六、一句话总结

**T1 把「找」做到极致（时间线、多入口、快速收藏）；T2 顺手把「管」补上（标签、理由、健康度、回顾）；T3 留给 AI 与生态，路径上全部复用现有「本地数据 + 同步状态机 + 搜索内核」三件套，不引入破坏性架构。**
